## AC3 — what changed, and why the measurement discriminates

The first run measured ONE socket arrival whose time tracked the suspend delay, which is the final
buffered document the criterion excludes by name. The fix (B-306) is in this cut. Same probe, same
route, same 800ms boundary, raw TCP socket rather than a `fetch` body because `fetch` coalesces:

| | v1.1.0-rc.1 | v1.1.0-rc.2 |
|---|---|---|
| socket arrivals | 1 | **3** |
| first arrival | +815ms, the whole document | **+8ms, the shell with `<head>`** |
| second arrival | — | +811ms, the resolved content |
| third arrival | — | +812ms, the hydration script |

The first chunk carries `<head>` and arrives 800ms before the boundary resolves. Varying the delay is
what makes this a measurement rather than one reading: on rc.1 a 60ms delay gave TTFB 73ms and an
800ms delay gave 815ms, so the arrival was the render finishing. Here it is not.

AC1's single arrival at +13ms is correct and not a contradiction: the root route declares no Suspense
boundary, and React emits the whole shell in one flush when nothing suspends. AC3 is the criterion
about chunking, and it was measured where chunking can be observed.
