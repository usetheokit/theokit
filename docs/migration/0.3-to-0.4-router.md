# Migration Guide: TheoKit 0.3 → 0.4 — Router Convention

> **0.4.0 locks the file-system routing convention to directory-nested only.**
> Dotted basenames like `auth.[provider].login.ts` are rejected at scan
> time with `RouterConventionError`. A codemod handles the migration in
> seconds. This guide tells you what changes, why, and how to fix it.

## TL;DR (3 commands)

```bash
# 1. Stop your dev server first (the codemod refuses to run while it's up).
#    Then run the codemod in dry-run to preview.
npx theokit migrate router --dry-run

# 2. Apply the migration.
npx theokit migrate router

# 3. Try the beta (no commit — installs in node_modules only).
npm install theokit@next
```

If `theokit migrate router` reports `alreadyClean: true` AND your tests
still pass against `theokit@next`, you're ready for `0.4.0-beta.0`.

## What changed

### Routes use directory nesting, not dotted basenames

Before (0.3.x):

```
server/routes/
├── auth.[provider].login.ts       ← URL: /api/auth.:provider.login (broken!)
├── posts.[id].ts                  ← URL: /api/posts.:id (broken!)
├── admin.sdk-config.ts            ← URL: /api/admin.sdk-config
└── debug.stability.last.ts        ← URL: /api/debug.stability.last
```

After (0.4.0):

```
server/routes/
├── auth/[provider]/login.ts       ← URL: /api/auth/:provider/login
├── posts/[id].ts                  ← URL: /api/posts/:id
├── admin/sdk-config.ts            ← URL: /api/admin/sdk-config
└── debug/stability/last.ts        ← URL: /api/debug/stability/last
```

### Why this is breaking (and why it's actually a bug fix)

In 0.3.x, the scanner used a greedy regex (`:(?:\.\.\.)?([^/]+)`) that
matched dotted basenames incorrectly:

- `auth.[provider].login.ts` produced **`paramNames: ['provider.login']`**
  (a single param-key with a literal dot inside it) — `params.provider`
  was always `undefined` at request time.
- `posts.[id].ts` produced **URL pattern `/api/posts.:id`** (literal dot,
  NOT slash) — a request to `/api/posts/42` would NEVER match.

Every dotted route was either silently producing wrong params or
completely unreachable. Code that depended on these routes was dead
code. The migration converts them to directory-nested form (the URL
shape your tests + client code were already expecting) and the
endpoints come alive.

This is why we ship **both the convention lockdown AND the codemod
together**: every dotted route becomes a working route on 0.4.0.

## Running the codemod

### Step 1 — Stop your dev server

The codemod refuses to run while `theokit dev` is up on port 3000 or
3100 (EC-2 — prevents a Vite watcher HMR cascade across the rename
storm).

```bash
# In whichever terminal `theokit dev` is running:
Ctrl+C
```

In CI / non-TTY, pass `--force` to skip the pre-flight:

```bash
npx theokit migrate router --force
```

### Step 2 — Preview the plan

```bash
npx theokit migrate router --dry-run
```

Sample output:

```
  → Migrating 23 dotted route(s) to directory-nested form...
     [dry-run] server/routes/admin.sdk-config.ts → server/routes/admin/sdk-config.ts
     [dry-run] server/routes/agents.[id].ts → server/routes/agents/[id].ts
     ...
```

### Step 3 — Apply

```bash
npx theokit migrate router
```

What it does:

1. Walks `server/routes/` and identifies every dotted basename.
2. Renames each file to its directory-nested form, splitting on `.`
   outside of `[...]` brackets. `git mv` is preferred (single rename
   in history); falls back to `mkdir -p && fs.rename` when not in a
   git repo.
3. Rewrites every relative `import { X } from './sibling'` inside the
   moved files so they continue to resolve correctly (`./sibling`
   becomes `../sibling` when the file gained one nesting level, etc.).
4. Reports counts to stdout.

The codemod is **idempotent** — running it twice on a clean tree is a
no-op.

### Step 4 — Verify

```bash
npx tsc --noEmit          # imports still resolve
npm test                  # behavior preserved
```

## Edge cases

### Co-located tests are skipped

The codemod (and the scanner) silently skip `*.test.ts` / `*.spec.ts`
files. Your `routes/posts/[id].test.ts` is safe.

### Case-only collisions (macOS, Windows)

If you have `auth.[provider].Login.ts` AND `auth/[provider]/login.ts`
(case-only difference), the codemod refuses to overwrite — it raises
`RouterMigrationCollisionError` and asks you to resolve manually.
On macOS HFS+/APFS and Windows NTFS those paths are the same; the
codemod errors on Linux too so behavior is consistent cross-platform.

### Partial-failure recovery

If the codemod crashes after migrating some files (e.g. `git mv`
returns an error mid-loop), it raises
`RouterMigrationPartialFailure` carrying `filesAlreadyMigrated[]`. Just
re-run the codemod — `planRouterMigration` is idempotent and will
skip the already-migrated files.

### Nested dotted parents

The codemod handles dotted segments at any depth. `api/v2/posts.[id].ts`
becomes `api/v2/posts/[id].ts` correctly. However, if a parent
**directory** itself uses a dotted name (e.g. `routes/v2.api/foo.ts`),
the codemod splits only the basename segment; rename the parent
directory manually first.

## Behavior changes summary (cheat sheet)

| 0.3.x | 0.4.0 |
|---|---|
| `auth.[provider].login.ts` accepted, `params.provider` undefined | Rejected with `RouterConventionError` at scan time |
| `posts.[id].ts` URL = `/api/posts.:id` (literal dot, unreachable) | Codemod converts to `posts/[id].ts`, URL = `/api/posts/:id` |
| Hot reload on routes change | Same + 50ms debounce so codemod-driven file storms don't crash dev server |
| No migration tooling | `theokit migrate router` (dry-run, force, idempotent) |

## Rollback

If something breaks after the migration:

```bash
# Pin back to 0.3.x
npm install theokit@latest        # currently 0.2.x — pin explicit if 0.3 promoted
```

Then revert the renames via git (the codemod prefers `git mv` so the
history is clean):

```bash
git revert <migration-commit-sha>
```

If `git mv` fell back to `fs.rename` because the project wasn't a git
repo at migration time, see the [Rollback Runbook](../runbook/0.3.0-rollback.md)
for manual recovery steps (mirror — applies equally to 0.4 renames).

## Polyglot services note

The router convention applies ONLY to TypeScript route files under
`server/routes/`. **Polyglot sidecars composed via `services: {}` in
`theo.config.ts` are UNAFFECTED** — they ship as separate processes
(FastAPI, Hono, etc.) with their own routing conventions, and theokit's
file-system scanner never reaches into them.

If your app uses both TS routes + a Python FastAPI sidecar, only the
TS side needs the codemod. The sidecar continues to expose its own
endpoints unchanged.
