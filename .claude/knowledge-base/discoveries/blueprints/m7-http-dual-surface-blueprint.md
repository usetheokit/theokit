# Blueprint: M7 — HTTP dual-surface consolidation (typed errors · health · programmatic boot)

> Distilled from fastify / hono / nitro / next.js (read-only clones under `.claude/knowledge-base/references/`) to lock the M7-1/M7-2/M7-3 API shapes for theokit's convention/filesystem-route server. Source plan: `.claude/knowledge-base/discoveries/plans/m7-http-dual-surface-plan.md` (discover-plan-confidence SHIPPABLE_WITH_CAVEATS 70.0).

## Context

theokit runs two HTTP surfaces that share almost no primitives. Surface A = the convention/filesystem-route dev-server (`theokit dev` → `startDevServer`, `theokit start` → `startCommand`); Surface B = the imperative `@theokit/http` `TheoApp` (which already has `/__theo/health`, typed exceptions). Surface A lacks: (M7-1) publicly-throwable typed errors + 404 ergonomics in `defineRoute` — the primitives `TheoError`/`fromUnknown`/`serverErrorToEnvelope`/`envelopeCodeToStatus` exist in `src/core/contracts/` but are unexported, and the legacy Node catch `src/server/http/handle-request-error.ts:35` emits a generic 500; (M7-2) a health/ready endpoint; (M7-3) a public programmatic boot (`startDevServer`/`startCommand` are CLI-internal — no `theokit/boot`). This blueprint grounds the API shapes in prior art. Respects `.claude/rules/architecture.md` (the principal `theokit` is never a dependency of other packages — all M7 changes are internal to `theokit`) and `.claude/rules/testing.md`.

## Objective

Lock the concrete API for: M7-1 (typed-error public export + `defineRoute` 404 + legacy-catch envelope wiring), M7-2 (`defineHealthRoute`/`defineReadyRoute`), M7-3 (`theokit/boot` returning a server handle) — with zero new runtime dependencies — so `/to-plan m7-http-dual-surface` can implement without re-researching.

## Coverage Corner 1 — Integration Tests

How the refs test that a thrown typed error yields the right status + body, and how the HTTP boundary is exercised.

- **Assert status + exact body envelope together, never separately.** Fastify's canonical suite drives a thrown error through `inject` and deep-equals the whole envelope: `reply.send(new Error('kaboom'))` → `res.statusCode === 500` AND `JSON.parse(res.payload)` deepEquals `{ error:'Internal Server Error', message:'kaboom', statusCode:500 }` (`fastify/test/500s.test.js:13-30`). Custom status + headers: `error.statusCode=400` + `error.headers` → status 400, header propagated, body `{error:'Bad Request',message:'kaboom',statusCode:400}` (`fastify/test/reply-error.test.js:362-383`); pure status-carry `err.statusCode=418` → 418 (`reply-error.test.js:195-206`); sub-400 floor `statusCode=399` → coerced (`reply-error.test.js:224`).
- **Test the "typed error's status overrides any default" invariant.** Hono: `new HTTPException(400, { res: new Response('An exception', { status: 200 }) }).getResponse().status === 400` (`hono/src/http-exception.test.ts:35-44`); base case `res.status===401` + `await res.text()==='Unauthorized'` + `exception.status===401` (`http-exception.test.ts:7-15`); cause chain preserved `exception.cause === error` (`http-exception.test.ts:32`).
- **Body is read off a Web `Response` triad** (`res.status`, `await res.text()/json()`, headers) — `hono/src/hono.test.ts:77-81`; 404 assertions `hono.test.ts:86`.

→ theokit M7 integration tests: one test per typed error asserting status + exact envelope together, plus an "override default status" case, fired in-process (no socket).

## Coverage Corner 2 — Dependencies

Whether typed-error + serialization needs a third-party dependency.

- **Fastify pulls deps for the serialize path — but for performance, not correctness.** `fastify/lib/error-serializer.js:6` requires `fast-json-stringify/lib/serializer` (the file is autogenerated, `error-serializer.js:1`); typed-error factory is `@fastify/error` (`fastify/package.json:209`); `fast-json-stringify: ^6.0.0` (`fastify/package.json:214`). Status text is stdlib: `require('node:http').STATUS_CODES` (`fastify/lib/error-handler.js:3`). The serialized shape is hardcoded `{statusCode, code, error, message}` (`fastify/lib/error-serializer.js:56-124`).
- **Hono is zero-runtime-dependency.** `hono/package.json` has ONLY a `devDependencies` block — no `dependencies`, no `peerDependencies` (`hono/package.json:667`). Its error serializes via Web `Response` (`hono/src/http-exception.ts:66-77`), no serializer lib.

→ **Verdict: theokit M7 ships ZERO new runtime deps.** A typed error class + `serverErrorToEnvelope` (already in-house) + `JSON.stringify` + `node:http`.`STATUS_CODES` covers it. `fast-json-stringify` is an optional perf optimization, not required.

## Coverage Corner 3 — Tools

The in-process (socketless) request API for boundary tests.

- **Fastify `app.inject({method,url,payload})`** returns `{statusCode, payload (raw string), headers}` without binding a port (`fastify/test/inject.test.js:28-33,55-56,95-97`); callback or chained-promise form (`inject.test.js:439-468`). Backed by `light-my-request: ^6.0.0` (`fastify/package.json:216`) — a test-only DEP.
- **Hono `app.request(input, requestInit?, Env?)`** is a thin wrapper that builds a Web `Request` and calls `this.fetch` (`hono/src/hono-base.ts:499-517`; string path normalized to `http://localhost{path}`, `:511`); JSDoc: "useful method for testing" (`:488`). Returns a Web `Response`. **Zero-dep.** Env injectable as 3rd arg (`hono/src/hono.test.ts:121`).

→ theokit `theokit/boot` should expose a `fetch`-handler + a Hono-style `request(input, init?) → Response` for in-process tests — zero-dep, aligned with theokit's universal fetch-handler contract; avoid Fastify's `inject` (drags `light-my-request`).

## Coverage Corner 4 — Techniques

The error / health / boot mechanisms.

**Error → status → serialized body (M7-1):**
- Fastify: status is intrinsic to the error (`createError(code,msg,statusCode)`, `fastify/lib/errors.js:3`; 404 = `FST_ERR_NOT_FOUND` w/ statusCode 404 + code, `errors.js:9-13`), resolved at send time with a hard sub-400→500 floor (`fastify/lib/error-status.js:7-12`); onError pipeline `defaultErrorHandler` → `setErrorHeaders` (re-derives from `error.status`/`error.statusCode` ≥400, `error-handler.js:159-166`) → `setErrorStatusCode` → `reply.send(error)` (`error-handler.js:86-101`); body assembled `{error:STATUS_CODES[statusCode], code, message, statusCode}` (`error-handler.js:112-117`). No `stack` in the wire body ever; logging severity branches `<500` info / `≥500` error (`error-handler.js:86-100`).
- Hono: `class HTTPException extends Error` with `readonly status` (default 500) (`hono/src/http-exception.ts:46-59`); `getResponse()` forces `this.status` over any provided `res` (`:66-77`); body = raw message string (no `{code,...}` envelope) — weaker (404 is just a number, no stable code).
- Nitro: delegates rendering to H3's `toResponse(error,event)` (`nitro/src/runtime/virtual/error-handler.ts:12`); only Nitro-side branch is `if (error.status !== 404) console.error(error)` — 404 special-cased to SUPPRESS logging (`error-handler.ts:9-11`).

**Health endpoint (M7-2):**
- Nitro reserved-namespace pattern: internal routes on `/_nitro/*` returning a plain object auto-serialized to 200 JSON (`nitro/src/runtime/internal/routes/dev-tasks.ts:19-31`); dev server mounts `/_vfs/**` BEFORE the catch-all `app.all("/**", ...)` (`nitro/src/dev/app.ts:63` then `:90`). Readiness = internal state, not a route: returns 503 + JSON `{error,hint}` + `Refresh:3` on every route when `!manager.ready` (`nitro/src/dev/server.ts:50,228-246`).
- Next: route modules dispatch by uppercase named export (`GET`/`POST`), `autoImplementMethods`/`resolveHandler` (`next.js/packages/next/src/server/route-modules/app-route/module.ts:331,391-396`), each returns a `Response`.
- fastify/hono: no built-in health route (community/user-defined).

→ liveness `defineHealthRoute` = always-200 `{status:"ok"}` on a reserved path (e.g. `/__theo/health`) registered BEFORE the filesystem catch-all; readiness `defineReadyRoute` = 200/503 from a registered probe (mirror nitro's internal-state→503-JSON). Keep them separate.

**Programmatic boot (M7-3):**
- Nitro: `createDevServer(nitro)` → `new NitroDevServer(nitro)` (`nitro/src/dev/server.ts:21-23`); `.listen(opts) : Server` calls srvx `serve({...opts, fetch:this.fetch})` and RETURNS the server handle (`dev/server.ts:135-146`), `.close()` (`:148-164`); fetch handler `this.fetch = app.fetch.bind(app)` (`dev/app.ts:26`). CLI is a thin wrapper: `new NitroDevServer(nitro); await server.listen({port,hostname})` (`nitro/src/cli/commands/dev.ts:60-65`) — SAME code path.
- Fastify: `fastify()` factory returns instance (`fastify/fastify.js:120,459`); `.listen()` dual promise/callback (`fastify/lib/server.js:31-34,106-124`) + `.inject()` over the shared `httpHandler` (`fastify.js:468-486,105`) — programmatic + network share one routing path.
- Hono: fetch-handler IS the surface — `fetch(request,...)` (`hono/src/hono-base.ts:479-485`), no port bind in core.

→ `theokit/boot` exports `startDevServer`/`startCommand` as public fns returning a handle `{ fetch, listen, close }`; the CLI becomes a thin arg-parse wrapper over the same fn (one code path); the `fetch` handler is exposed for socketless tests.

## ADRs

### D1 — Typed errors: carry status on the error, derive + floor at the boundary; fixed envelope; typed 404
**Decision:** publicly export theokit's existing `TheoError`/`fromUnknown`/`serverErrorToEnvelope`/`envelopeCodeToStatus`; wire the legacy Node catch (`handle-request-error.ts`) through `serverErrorToEnvelope` + `envelopeCodeToStatus` (sub-400 → 500 floor); add a typed Not-Found constant + `defineRoute` 404 ergonomics; envelope stays `{statusCode,code,error,message}`; stack only in logs. **Rationale:** mirrors fastify (`error-status.js:9` floor; `error-serializer.js:56-124` fixed envelope; `errors.js:9-13` typed 404) and hono's status-wins (`http-exception.ts:66-77`); theokit already owns the primitives. **Alternatives rejected:** hono's bare-message body (no stable `code`, weak 404); per-route try/catch (doesn't centralize).

### D2 — Health: reserved-namespace `defineHealthRoute`/`defineReadyRoute`, liveness ≠ readiness
**Decision:** register liveness (always-200 `{status:"ok"}`) + readiness (200/503 from a probe) on a reserved path injected BEFORE the filesystem catch-all. **Rationale:** nitro's `/_nitro/*` + `/_vfs/**`-before-catch-all (`dev/app.ts:63,90`) + readiness-as-state-503 (`dev/server.ts:50,228-246`). **Alternatives rejected:** single combined `/health` (conflates liveness/readiness); magic user path (collides with user routes).

### D3 — Boot: public `theokit/boot` returning a `{fetch,listen,close}` handle; CLI is a thin wrapper
**Decision:** promote `startDevServer`/`startCommand` to a public `theokit/boot` subpath returning a handle exposing `fetch` (socketless), `listen` (network), `close`; the CLI calls the same fn (one code path). **Rationale:** nitro `createDevServer().listen():Server` + CLI wrapper (`dev/server.ts:135-146`, `cli/commands/dev.ts:60-65`); fastify shared `httpHandler` for `.listen`/`.inject` (`fastify.js:468-486`); hono fetch-as-surface (`hono-base.ts:479-517`). **Alternatives rejected:** void-returning boot (no programmatic close/embed); `light-my-request` inject (adds a dep — use the zero-dep fetch handler instead).

## Recommendations

Concrete decisions per research question, mapped to M7-1/2/3 (all internal to `theokit`, zero new runtime deps):

1. **M7-1 (Q1/Q6):** Export `TheoError`, `fromUnknown`, `serverErrorToEnvelope`, `envelopeCodeToStatus`, and a typed `NotFoundError`(404) from a public surface (extend `theokit/server` define/http barrel — NOT a new dep). Rewrite `handle-request-error.ts`'s legacy catch to: `const env = serverErrorToEnvelope(fromUnknown(err)); res.statusCode = envelopeCodeToStatus(env.code) (floor <400→500); send JSON env`. Add `defineRoute` 404 ergonomics (throw `NotFoundError` or return a not-found sentinel → 404 envelope). Envelope `{statusCode,code,error,message}`; stack only in the log path. Tests: per-error status+envelope deep-equal + an override-default-status case (fastify `500s.test.js:13-30`, `reply-error.test.js:362-383`; hono `http-exception.test.ts:35-44`).
2. **M7-2 (Q2):** Ship `defineHealthRoute(handler?)` (default → 200 `{status:"ok"}`) and `defineReadyRoute(probe)` (200 `{status:"ready"}` / 503 `{status:"not-ready",...}`) that the filesystem scan registers on `/__theo/health` + `/__theo/ready` BEFORE the catch-all. Plain-object return auto-serialized. Tests: in-process `request('/__theo/health')` → 200 + `{status:"ok"}`; ready probe failure → 503.
3. **M7-3 (Q3/Q5):** `theokit/boot` exports `startDevServer(opts)`/`startCommand(opts)` returning `{ fetch(req):Response, listen(opts):Promise<handle>, close():Promise<void> }`. CLI `dev`/`start` commands become thin wrappers over these. Tests use the returned `fetch`/`request` (Hono `app.request` shape, `hono-base.ts:499-517`) — socketless, zero-dep — including the M7-2 health route and an M7-1 typed-error route end-to-end.
4. **Dependencies (Q4):** confirmed ZERO new runtime deps — `node:http`.`STATUS_CODES` + in-house `serverErrorToEnvelope` + Web `Response`/`JSON.stringify`.
