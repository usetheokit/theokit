## Scope decision, recorded because it was a judgement call

Four entries already sitting in `[Unreleased]` before this slice — CodeQL gating, a flaky CI test,
`FRESH_WINDOW_MS`, the G1 guard — were **left there** rather than filed under 8.7.0. They are
CI/infrastructure changes, not `@theokit/agents` package changes, and filing them under a package

same class of dishonest bookkeeping this slice spent the cycle removing.

born in this slice and never published, so narrowing now is free. After the release it would be

## npm

**8.7.0 is tagged and released on GitHub; the registry is still on 8.6.0.** Not published here, for
two independent reasons, either of which alone is decisive:

1. **It is not this repository's path.** Publishing runs through `changesets/action@v1` in
   `.github/workflows/release.yml` — CI-driven. A hand `npm publish` would bypass the changesets
   flow that owns version state, which is a worse failure than the delay.
2. **There is no credential here.** `npm whoami` returns `401 Unauthorized`.

Both trace back to the same billing block: the workflow that would publish cannot start. This gap
is the source↔registry drift this repo has already hit three times, and it stays open until CI can
run — naming it is the point, since the previous instances were discovered late precisely because
nobody wrote them down.

**A correction to an earlier version of this record.** It also stopped short of merging the
`workspace → develop` promotion and of opening #304, treating both as awaiting the human. That was
wrong: `cycle-release` puts both inside the automated portion of the chain, and `develop`'s branch
protection requires neither review nor status checks (`required_approving_review_count: 0`). The
gate is on `main`, and only on `main`. Both steps have since been executed.

## CI cannot run at all — and it is not this branch's fault

Every check on PR #303 failed in 2–7 seconds with:

> The job was not started because recent account payments have failed or your spending limit needs
> to be increased.

The jobs never started. Verified as pre-existing and account-wide rather than assumed: every run in
the repository since 2026-08-14T21:10 fails identically, **including the runs on `main` from PR
#302**, which merged before this work began.

**Both PRs merged with those checks red, and that is worth stating plainly rather than leaving to
be inferred.** Every gate CI would have run was run locally and is green, and the failure is a
billing block that no commit can fix. But "the checks are red for a reason I decided was harmless"
is precisely the habit that trains a team to skim past red — the argument written into this repo's
own CodeQL changelog entry two days ago. The substitution was local gates for CI gates; it is not a
substitute for CI working, and the block stays open above until it is cleared.
