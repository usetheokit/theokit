## Scope decision, recorded because it was a judgement call

Four entries already sitting in `[Unreleased]` before this slice — CodeQL gating, a flaky CI test,
`FRESH_WINDOW_MS`, the G1 guard — were **left there** rather than filed under 8.7.0. They are
CI/infrastructure changes, not `@theokit/agents` package changes, and filing them under a package
version would assert something untrue about what a consumer receives when they upgrade. That is the
same class of dishonest bookkeeping this slice spent the cycle removing.

`secure-store` was withdrawn from the `./hooks` barrel **in this same cut**, deliberately: it was
born in this slice and never published, so narrowing now is free. After the release it would be
breaking.

## Why the chain stops here

Two reasons, and only one of them is procedural.

**1. The human-approval gate (by design).** Unbreakable Rule 4: `main` is reached only through an
approved PR, and auto-merge is forbidden. `PR_OPEN_AWAITING_APPROVAL` is the correct terminal state
for an autonomous run.

**2. CI cannot run at all — and it is not this branch's fault.** Every check on PR #303 failed in
2–7 seconds with:

> The job was not started because recent account payments have failed or your spending limit needs
> to be increased.

The jobs never started. Verified as pre-existing and account-wide rather than assumed: every run in
the repository since 2026-08-14T21:10 fails identically, **including the runs on `main` from PR
#302**, which merged before this work began.

The promotion PR is `MERGEABLE`; its state is `UNSTABLE` purely because those checks are red.

**This is not merged past.** Every gate CI would have run was run locally and is green — but "the
checks are red for a reason I decided was harmless" is precisely the habit that trains a team to
skim past red, which is the argument written into this repo's own CodeQL changelog entry two days
ago. The billing block is the account owner's to clear.
