## Follow-up — post-publish npm smoke (theokit@0.15.2)

After the 0.15.1 publish, a **post-publish smoke on the npm end-user path** (scaffold from the
*published* `create-theokit@1.0.16` + run `npm install`, not the pnpm path the dogfood used) found a
real V1 blocker: a fresh `npx create-theokit` failed `npm install` with an `@theokit/ui` peer
`ERESOLVE`. `theokit@0.15.1`'s optional `@theokit/ui` peer (`^0.14.0 || ^0.18.0 || ^0.19.0`) did not
cover the published stable major `@theokit/ui@1.0.0` that the template pins (`^1.0.0`). npm is strict
on optional-peer conflicts; pnpm only warns — which is why the dogfood missed it.

Fixed in **`theokit@0.15.2`** (PR #76 fix, PR #77 Version Packages): the peer range now includes
`^1.0.0`. Also refreshed two stale `@theokit/ui`-peer tests + the `create-theo-default-template`
`@theokit/sdk` pin guard (`^1` → `^2.13` compaction floor) the M6 pin bump had left behind.

**Proven end-to-end on the PUBLISHED bits (no overrides):** `npx create-theokit@1.0.16` →
`npm install` (theokit 0.15.2 · @theokit/agents 0.30.1 · @theokit/ui 1.0.0 · @theokit/sdk 2.18.1,
0 vulnerabilities) → `theokit build` ✓ (built in 4.80s). `create-theokit` needed no re-publish — its
template pins `theokit@^0.15.1`, which resolves to 0.15.2.

Known separate debt (NOT M6, pre-existing on develop): a few red unit tests —
`cli-cleanup-rename` (barrel that doesn't exist), `r3a-web-crypto-migration-leaf` (2 `node:*` imports
outside the allowlist), `devtools-treeshake` (repo fixture lacks `@usetheo/ui` in its install; the
end-user build is proven to work), and a few collection-error files. Deserve a dedicated
stabilization pass.
