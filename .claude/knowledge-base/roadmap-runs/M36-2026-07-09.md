# Milestone M36 — Tauri desktop surface

## Objective (from ROADMAP.md)

A working Tauri desktop app that streams a real agent turn, reusing the M35 in-process path via a
sidecar, gated on a push-transport ADR (the Request→Response waist cannot express Channel/emit).

## Outcome

Realized. **ADR-0045** (the GATE) decides the push transport: Node sidecar runs the agent via M35's
`streamAgentTurnInProcess` (single process, no HTTP) and emits JSONL over stdout; the Tauri Rust shell
reads `CommandEvent::Stdout` and pushes each chunk to the webview via a **`Channel<String>`** (docs:
events are "not designed for low latency"; Channel is the streaming path for child-process output).
HITL is bidirectional (approval-request over stdout, decision over the sidecar's stdin).

**No framework-core change** (ADR-0045 D5): the sidecar imports the EXISTING M35 seam; all Tauri
specifics live in `theo-code-v2/apps/desktop/` (sidecar-core.ts, sidecar.ts, src-tauri Rust, webview).
`build --target` stays emit-only.

**Evidence** (`theo-code-v2/apps/desktop/EVIDENCE.md`): Rust shell compiles + runs (`cargo build`,
webkit2gtk, DISPLAY=:0); sidecar streams a real turn (`SIDECAR-OK`); HITL round-trip over stdin
executed a gated tool (`DESKTOP_HITL_OK`, exit 0); contract test (2) + Rust unit tests (2, incl. an
adversarial JSON-injection test) green. Independent review: NEEDS_FIXES → all 7 findings (1 BLOCKER +
2 HIGH + 2 LOW + INFO) fixed and re-verified.

DoD: push-transport ADR (gate) ✅, sidecar reuses M35 ✅, working app (streams a turn) ✅, contract
test + build ✅, docs + gates ✅.
