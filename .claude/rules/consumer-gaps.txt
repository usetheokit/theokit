# Consumer gap register — the local half of a channel that did not exist.
#
# The consumer's own register (`TheoCode/BACKLOG.md § Upstream`) lists gaps measured against this
# repo. Verified 2026-08-16: it says 8 are open and none is fully open — five had been closed and
# reached that consumer BY ACCIDENT, because the same person maintains both sides. A customer without
# that overlap keeps reading "open" against capabilities that ship, and keeps rebuilding them.
#
# This file is what `scripts/check-changelog-closes.mjs` reads: when a change touches one of these
# paths, `CHANGELOG.md`'s `[Unreleased]` section must name the gap id, so the closure is discoverable
# in the artifact the consumer already reads.
#
# It is a CONVENTION with a mechanical check, not a notification system. It does not push.
#
# Format:  U-N | comma-separated paths (a trailing / means everything under it) | one-line summary
# Warn mode: a missing `closes:` prints, it does not block. The register is a heuristic about which
# files answer which gap, and a heuristic that blocks CI teaches people to route around it.
