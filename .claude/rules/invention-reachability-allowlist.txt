# Invention-reachability allowlist
#
# Exemptions for `scripts/check-invention-reachability.mjs` — the gate that asks whether a capability
# the layer INVENTS is reachable, or crossed the boundary as a type with its enforcement left behind.
#
# The gate is a heuristic (an exported decision-shaped type + a function in the same module taking
# it), so false positives are expected and this file is how they are answered. It is NOT how real
# findings are silenced: every entry carries a sunset, and an entry past its sunset is IGNORED — the
# finding re-fires at full severity, per `code-quality-golden-rule.md § 4`. An exemption that never
# expires is where findings go to be forgotten.
#
# Format:  SYMBOL | SUNSET (YYYY-MM-DD) | RATIONALE
# Sunset window: <= 90 days from the day the entry is added.
#
# Adding an entry requires a CHANGELOG line under [Unreleased] § Changed.

# Both entries below are the same class of false positive, and it is worth naming: the enforcement is
# NOT missing — it runs automatically at the seam where the consumer supplies the value. The gate
# cannot see that, because it looks inside one module and the seam is in another. A human decided
# each one; the sunset is when someone has to decide again.

ApprovalPosture | 2026-11-14 | `applyPosture` runs inside `toAgentFactory` when the posture is passed, so a consumer never calls it. The half a consumer DID need — the per-event "may I auto-approve this tool now?" predicate — was the real gap and is now `shouldAutoApprove` in bridge/approval-decision.ts (T2.1).
