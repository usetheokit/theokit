# SWC Plugin Development Guide

SWC plugins are WebAssembly modules written in Rust that transform JavaScript/TypeScript ASTs.

## Environment Setup

```bash
# 1. Install Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. Add WASM target
rustup target add wasm32-wasip1

# 3. Install SWC CLI (for scaffolding)
cargo install swc_cli

# 4. (Optional) Install rust-analyzer for IDE support
```

## Create a New Plugin

```bash
swc plugin new --target-type wasm32-wasip1 my-first-plugin
cd my-first-plugin
```

This generates a scaffold with `Cargo.toml`, `src/lib.rs`, and test fixtures.

## Plugin Structure

```rust
use swc_core::ecma::{
    ast::Program,
    transforms::testing::test,
    visit::{visit_mut_pass, VisitMut, VisitMutWith},
};
use swc_core::plugin::{plugin_transform, proxies::TransformPluginProgramMetadata};

pub struct TransformVisitor;

impl VisitMut for TransformVisitor {
    // Implement visitor methods here
    // e.g., visit_mut_bin_expr, visit_mut_call_expr, visit_mut_ident, etc.
}

#[plugin_transform]
pub fn process_transform(program: Program, _metadata: TransformPluginProgramMetadata) -> Program {
    program.apply(visit_mut_pass(TransformVisitor))
}
```

## Key API Changes (Recent)

| Old | New |
|-----|-----|
| `chain!` macro | Tuple syntax `(pass1, pass2)` |
| `-> impl Fold` | `-> impl Pass` |
| `as_folder` | `visit_mut_pass` |
| `program.fold_with(&mut visitor)` | `program.apply(visit_mut_pass(visitor))` |
| — | `noop_pass()` from `swc_ecma_ast` |

## Visitor Methods

Implement methods on `VisitMut` to transform AST nodes:

```rust
impl VisitMut for TransformVisitor {
    // Visit and modify binary expressions (e.g., a === b)
    fn visit_mut_bin_expr(&mut self, e: &mut BinExpr) {
        e.visit_mut_children_with(self); // ALWAYS visit children first
        if e.op == op!("===") {
            e.op = op!("==");
        }
    }

    // Visit and modify identifiers
    fn visit_mut_ident(&mut self, ident: &mut Ident) {
        // Rename variables, etc.
    }

    // Inject/remove statements
    fn visit_mut_stmts(&mut self, stmts: &mut Vec<Stmt>) {
        stmts.visit_mut_children_with(self);
        // Add new statements
        // Remove statements with retain()
    }

    // Inject/remove module items (imports, exports, statements)
    fn visit_mut_module_items(&mut self, items: &mut Vec<ModuleItem>) {
        items.visit_mut_children_with(self);
    }
}
```

**Important:** Always call `e.visit_mut_children_with(self)` to process child nodes.

## Common Patterns

### Matching Box<Expr>

All expressions are stored as `Box<Expr>`:

```rust
fn visit_mut_callee(&mut self, callee: &mut Callee) {
    if let Callee::Expr(expr) = callee {
        if let Expr::Ident(i) = &mut **expr {
            // Work with identifier
        }
    }
}
```

### State Management

Use struct fields for state across visitor calls:

```rust
pub struct TransformVisitor {
    counter: usize,
    in_async_fn: bool,
}

impl VisitMut for TransformVisitor {
    fn visit_mut_fn_decl(&mut self, f: &mut FnDecl) {
        let old = self.in_async_fn;
        self.in_async_fn = f.function.is_async;
        f.visit_mut_children_with(self);
        self.in_async_fn = old; // Restore state
    }
}
```

### Node Deletion (Mark & Delete)

```rust
fn visit_mut_stmts(&mut self, stmts: &mut Vec<Stmt>) {
    stmts.visit_mut_children_with(self);

    // Mark for deletion using take()
    for stmt in stmts.iter_mut() {
        if should_remove(stmt) {
            stmt.take(); // Marks as invalid
        }
    }

    // Remove marked nodes
    stmts.retain(|s| !matches!(s, Stmt::Empty(..)));
}
```

## Testing

### Fixture-based tests

```rust
use swc_core::ecma::transforms::testing::test_fixture;
use std::path::PathBuf;

#[testing::fixture("tests/fixture/**/input.js")]
fn fixture(input: PathBuf) {
    let output = input.parent().unwrap().join("output.js");
    test_fixture(
        Default::default(),
        &|_| visit_mut_pass(TransformVisitor),
        &input,
        &output,
    );
}
```

Run tests: `cargo test`
Update snapshots: `UPDATE=1 cargo test`

### Logging

```rust
// Use tracing crate
tracing::debug!("Processing node: {:?}", node);
```

Run with logging: `RUST_LOG=trace cargo test`

## Selecting swc_core Version

Match `swc_core` version to `@swc/core` version. Check compatibility at:
https://swc.rs/docs/plugin/selecting-swc-core

## Limitations

- Decorators and TypeScript types are processed BEFORE plugins — not available in WASM plugins
- Use Linux path conventions in WASM (replace `\\` with `/`)
- Top-down traversal preferred; upward traversal requires manual parent context storage
- No direct Babel-style `path` API — cache parent info in struct fields instead

## Publishing

After development and testing, publish to npm as a standard package. The compiled `.wasm` file is the plugin artifact. See https://swc.rs/docs/plugin/publishing for details.
