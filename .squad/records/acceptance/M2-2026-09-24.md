## Why AC3 failed, and how it was separated from a measurement artefact

AC3 asks that the first streamed chunk carry `<head>`, "observed chunk-by-chunk rather than on the
final buffered document". Against `/` the whole document arrived in **one** chunk. That alone proves
nothing: the scaffold declares **zero** `Suspense` or `lazy` boundaries of its own, and with nothing
suspending React emits the entire shell in a single flush — correct behaviour, not a defect. With one
chunk, "the first chunk" and "the buffered document" are the same bytes, so the observation cannot
discriminate the two renderers the criterion exists to separate.

So the condition was created: a temporary route declaring a boundary that actually suspends, read at
the **raw TCP socket** rather than through a `fetch` body, because `fetch` coalesces and a socket does
not. Then the delay was varied, which is what turns one reading into a measurement:

| suspend delay | first socket arrival | arrivals |
|---|---|---|
| 60 ms | +73 ms | 1 |
| 800 ms | +815 ms | 1 |

The arrival time tracks the delay. The shell is withheld until the render completes, so what is served
IS the final buffered document — the case the criterion excludes by name.

Three facts kept the diagnosis honest in the other direction: `Transfer-Encoding: chunked` **is**
declared, the document carries both the fallback and the resolved value, and React's `$RC`/`$RS`
substitution bootstrap is present. The renderer streams. What does not stream is what reaches the
socket.

## Root cause

The build emitted the **non-streaming** entry although the config declares the flag. Evidence in
`m2-ac3-root-cause.txt`:

- `my-test/.theokit/server/entry-server.js:2446-2447` exports `render` and nothing else; a grep for
  `renderStreamingNode` / `renderStreamingWeb` / `streaming: true` in that file returns **0**.
- That `render` accumulates: `html += chunk.toString()` at `:2423`, `resolve({ html, hydrationData })`
  on `end` at `:2426`. No byte is observable before the render finishes.
- With no streaming export, `ctx.ssrRenderStreaming` is undefined, so
  `packages/theo/src/cli/commands/start/request-handler.ts:169` returns false and every request takes
  the synchronous path.

The generator is not missing the capability — `packages/theo/src/router/entry-server.ts:300-335`
emits an `onShellReady` entry that writes the head before React produces a byte. It is not what the
build selected.

**AC1 passed through that synchronous path.** The criterion asks for a parseable document carrying
`<head>` and the hydration script, and it gets one; it does not ask which path produced it. Recording
this is the difference between a pass and a pass nobody can interpret later.
