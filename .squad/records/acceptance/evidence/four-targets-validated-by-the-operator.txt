     account_sso_login: true, context 'all' — an ACCOUNT-level setting inherited by the site,
     with has_password: false. Nothing about the deploy or the function was wrong. Cleared with
     `netlify api updateSite --data '{"site_id":"...","body":{"sso_login":false}}'`, after
     which the same deploy answered 200. A deploy that is refused at the edge is
     indistinguishable from a broken one unless the response body is read.

  2. aws-lambda REFUSES ssrStreaming: true, and the refusal is correct. A Lambda v2 result
     carries its body as a string, so nothing can leave the function before the run ends;
     streaming would need awslambda.streamifyResponse plus a Function URL in RESPONSE_STREAM
     mode, which this adapter does not emit. The build names the six targets that do stream.
     Built from a scratch copy with streaming off rather than by editing the shared project.
