SECOND RUN, same day, after two more fixes. Version f53798ed-34de-42d6-ad7e-822d1c1fc47f.

FIX 4 — wrangler.toml never set `run_worker_first`, so Cloudflare's asset handler answered
  every path matching a file (including `/` -> index.html) BEFORE the worker ran. The document
  came off the CDN as a static shell and the code that renders it, and that stamps the security
  baseline, never executed. Now:
      run_worker_first = ["/*", "!/assets/*"]
      not_found_handling = "none"        (only when ssrStreaming; SPA fallback otherwise)
  The negation keeps the 307 hashed build outputs on the CDN path.

  Owning `/` also means receiving `/robots.txt` and `/logo.png`, which must NOT be rendered as
  documents. The worker now splits on an extension in the last path segment.

FIX 5 — `withSecurityHeaders` did `headers.set()` on a response it did not construct. A Response
  from a binding carries an immutable headers guard. Read from `wrangler tail --format json`:

      TypeError: Can't modify immutable headers.
        at withSecurityHeaders (worker.js:69439:55)
        at handleRequest (worker.js:102382:14)
      GET /robots.txt -> HTTP 500, "error code: 1101"

  It had never fired because every response it had been handed was one the framework built. The
  only paths handing it a FOREIGN response are Cloudflare's asset branches, which were unreachable
  until fix 4 landed. The line was shipped and unreachable. The function is shared by all six
  targets, so the fix is in the shared function.
