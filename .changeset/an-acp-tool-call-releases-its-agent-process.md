An ACP tool call releases the agent process it spawned, and a failing agent rejects the call instead of crashing the host or hanging it. The tool returned by `createACPTool` started a coding-agent process on every call and never ended it, so each call left one more process running. It now closes its transport when the call ends, on a reply, a refused step or an error. `NodeAcpTransport` listens for the process failing, its stdin breaking and the process exiting, so a command that does not exist rejects the call with `AcpTransportClosedError` naming the command, where it used to throw an uncaught `ENOENT` that took the host down, and an agent that exits mid-turn rejects with the same error and its exit code instead of leaving the call pending forever. Each request of the turn now has a timeout, `timeoutMs` in `AcpToolConfig` (default `DEFAULT_ACP_TIMEOUT_MS`, ten minutes); an agent that does not answer within it rejects the call with `AcpRequestTimeoutError`, naming the method. A `timeoutMs` that is not a positive finite number is refused when the tool is created. `AcpToolTransport` types a factory transport that can be closed and can report closing; a plain `AcpTransport` still works.
