`defineCachedRoute` now runs the handler once per cache key when requests for that key arrive together. Before, 10 concurrent misses of one key ran the handler 10 times, and 10 concurrent stale hits started 10 background revalidations. Requests that arrive while a key's handler is running wait for it and each build their own `Response` from the cached value (`X-Theo-Cache: MISS`). When the response is not cacheable (it carries `Set-Cookie`, streams, has an uncached error status, or `cacheable` refuses it), it stays with its own request, and each waiting request runs the handler itself. When the handler throws, every waiting request rejects with the same error, unless the first request's own client aborted. That exception needs a request signal, so it does not apply to a Node `IncomingMessage`. A stale key starts one background revalidation at a time, and the key is freed when the run settles. A background revalidation that fails keeps the stale entry and is now reported once per route with `console.warn`, where before it was swallowed. (B-667)
